## Controller

- For each externally connected device, the OS needs a **software representation (driver)** and sometimes a **hardware controller**.
    
- In theory, each device type would need a separate driver/controller, but standards simplify this:
    
    - **USB controller**: A single generalized controller can handle a wide range of USB devices (mice, keyboards, storage, etc.). The device-specific logic is often in the driver.
        
    - **Memory controllers**: These are specialized (e.g., DRAM controllers) because memory access has very strict timing/organization requirements.
        
    - **Video controllers (GPU/graphics card)**: Also specialized, since rendering and display require dedicated hardware and software support.

## Basic Terminologies

### Bootstrap Program

- The **bootstrap program** (firmware, e.g., stored in ROM/Flash) initializes the system.
    
- It performs hardware checks and loads the operating system into memory.
    
- On PCs, this is handled by **BIOS/UEFI**, which finds the **MBR (Master Boot Record)** or **bootloader** to start the OS.
    
- If multiple OSes/drives exist, a **bootloader** (e.g., GRUB) helps select which OS to load.
    

---

### Interrupts

- An **interrupt** is a signal sent to the CPU (by hardware or software) to indicate an event needing attention.
    
- CPU saves the current execution state, then jumps to the **Interrupt Service Routine (ISR)** (also called **interrupt handler**).
    
- Types:
    
    - **Hardware interrupt**: From devices (keyboard input, timer, disk I/O finished).
        
    - **Software interrupt (system call/trap)**: From programs requesting OS services.
        

---

### System Call

- A **system call** is a controlled way for software to request services from the OS (like file read, memory allocation, process management).
    
- Unlike interrupts from hardware, system calls are generated intentionally by a running program.
    
- They switch CPU mode from **user mode → kernel mode** to safely access OS functionality.
    

---

### Service Routine

- The **service routine** (interrupt handler) is the code the CPU executes when an interrupt/system call happens.
    
- Located in a fixed or registered place in memory (via the **interrupt vector table**).
    
- Example: Keyboard interrupt → CPU runs keyboard ISR → places input in buffer → resumes normal execution.
